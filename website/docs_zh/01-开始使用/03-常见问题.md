# 常见问题（FAQ）

本页汇总使用 Tydora 时的高频问题与排错思路。若未覆盖你的问题，欢迎到 GitHub Issues 反馈（见 [[01-开始使用/02-关于]]）。

## 入门与基础

### 第一次打开该选哪个仓库？

仓库就是「一个本地文件夹」。建议为不同用途建不同文件夹（如 `工作笔记`、`个人知识库`），再通过仓库切换器分别添加。详见 [[04-文件管理/01-仓库]]。

### 文件会被移动或修改吗？

不会。Tydora 只读取与写入你指定的文件，**不会**移动、复制或改动仓库结构。移除仓库也只是解除引用。详见 [[04-文件管理/01-仓库]]。

### 删除的笔记能恢复吗？

**不能。** 删除操作不可撤销，且会递归删除文件夹内全部内容。重要资料请先备份或纳入 Git 等版本管理。

## 编辑与快捷键

### 为什么 `Ctrl+O` 的行为和文档里「有序列表」不一致？

这个组合在默认配置中**同时绑定了两个命令**（`Ctrl+O`：快速打开 + 有序列表）。运行时**全局命令优先**，所以 `Ctrl+O` 实际打开文件。若你常用有序列表快捷键，请在 [[07-设置/03-快捷键设置]] 中为其重新分配。详见 [[07-设置/04-快捷键速查]]。

### 怎么在即时渲染和源码之间切换？

按 `Ctrl+/` 一键切换；或点底部状态栏的模式指示。详见 [[02-编辑器/01-编辑模式]]。

### 表格怎么快速增删行列？

在即时渲染下，把光标放入表格会出现浮动工具栏；快捷键见 [[07-设置/04-快捷键速查]] 的「表格」分组。详见 [[02-编辑器/08-表格操作]]。

## 知识管理

### `[[双链]]` 点击没反应 / 显示找不到？

- 确认链接的笔记名拼写正确，且存在于当前仓库
- 链接解析依赖 [[03-知识管理/05-链接索引]]，首次打开大仓库时索引可能仍在构建，稍候即可
- 文件名改过名时，Tydora 会尝试修复旧链接；若仍失效，检查是否跨仓库（链接默认只在当前仓库内解析）

### 反向链接为空，是正常的吗？

正常。只有**其他笔记链接到当前笔记**时，反向链接才会出现条目。没有反向链接的笔记可能是「信息孤岛」，可主动补链。详见 [[03-知识管理/03-反向链接]]。

### 知识图谱是空的？

图谱只展示存在 `[[03-知识管理/01-Wiki链接]]` 关系的笔记。若仓库里还没有任何双链，图谱自然为空。先建立几条链接再看。详见 [[03-知识管理/04-知识图谱]]。

## 渲染与显示

### 数学公式不显示？

- 确认在 [[07-设置/02-编辑器设置]] 中开启了「数学公式」
- 检查语法：行内用 `$...$`，块级用 `$$...$$`
- 个别复杂公式在 KaTeX 下报错，可切换到 MathJax 引擎

### Mermaid 图表没渲染？

- 确认代码块语言标注为 `mermaid`，且「Mermaid 图表」开关已开
- 检查语法括号、箭头是否配对，可对照 [Mermaid 官方文档](https://mermaid.js.org/)
- 详见 [[02-编辑器/05-Mermaid图表]]

### 界面显示异常（样式错乱、图表不更新）？

尝试在 [[07-设置/02-编辑器设置]] 中「清除缓存」，重启应用后通常可恢复。

### 主题/代码高亮想换？

- 应用主题：[[06-主题与外观/01-内置主题]]（9 款）或导入 [[06-主题与外观/02-Typora主题]]
- 代码配色：[[06-主题与外观/03-代码高亮主题]]（11 款）

## 发布与更新

### 提示「未找到 markdown-publish CLI」？

发布功能依赖的 CLI 没有随安装包分发，需要手动装一次：先安装 [Node.js](https://nodejs.org)，再执行 `npm install -g @abstractwebunit/markdown-publish`，然后重启 Tydora。详见 [[08-高级功能/01-发布网站]]。

### 发布到 GitHub Pages 后资源 404？

多半是 Base Path 没设对。在发布配置中把「Base Path」填为 `/<仓库名>/`，「站点 URL」填 `https://<用户名>.github.io/<仓库名>/`。详见 [[08-高级功能/01-发布网站]]。

### 只想发布部分笔记怎么办？

用「仅公开笔记」模式，并在要公开的笔记 Frontmatter 写 `publish: public`。详见 [[08-高级功能/01-发布网站]] 与 [[02-编辑器/07-Frontmatter]]。

### 自动更新失败 / 一直提示签名错误？

通常是签名密钥或 GitHub Secret 配置问题。请核对 [[09-blog/自动更新配置]] 中的密钥生成、Secret 填写与 `tauri.conf.json` 公钥。
